# Test 1 - Interactive Shell in Nginx

## Objective

Determine whether an interactive shell can be opened inside the running Nginx container and whether the activity is detected by the default Falco rules.

## Command

```bash
kubectl exec -it deployment/nginx-lab -- /bin/sh
```

Inside the container:

```bash
whoami
```

## Expected Result

An interactive shell should open inside the Nginx container.

Falco may generate a shell-related warning depending on the default rules available in the installed Falco version.

## Actual Result

The interactive shell opened successfully inside the Nginx container.

The `whoami` command confirmed that commands could be executed from inside the container.

## Falco Detection

**Not detected**

The Falco logs were reviewed using:

```bash
kubectl logs -n falco -l app.kubernetes.io/name=falco -c falco --since=5m | grep Warning
```

No warning related to the interactive shell activity was generated by the default Falco rules.

## Security Risk

Interactive shell access allows a user with sufficient Kubernetes permissions to execute commands directly inside a running container.

If an attacker obtains this level of access, they may inspect files, modify application data, execute additional commands, or attempt further actions from inside the workload.

## Recommended Mitigation

- Restrict Kubernetes `exec` permissions using RBAC.
- Run containers as non-root users.
- Remove unnecessary Linux capabilities.
- Disable privilege escalation.
- Use runtime monitoring rules designed to detect interactive shell activity.

## Test Result

**Successful test / No Falco alert generated**

The shell-access test worked as expected, but the installed default Falco rule set did not generate a warning for this activity.
